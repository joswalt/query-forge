## Decisions so far

- [Desktop framework compatibility research](issues/01-desktop-framework-research.md): Electron runs the official JS Azure SDKs unmodified; Tauri has no Node runtime and would need pre-1.0 Rust crates or a Node sidecar (+40-80MB, extra packaging step). Credential storage/SQLite/signing are mature on both, shaped differently. No recommendation — feeds ticket 02.
- [Desktop framework decision](issues/02-desktop-framework-decision.md): **Electron.** SDK stability and single-language simplicity won over Tauri's size/memory edge; MVP doesn't need multi-window; Wails dropped (third language, smallest ecosystem). Unblocks 06, 07, 08, 09; moots the Tauri-specific conditionals on tickets 04 and 05.
- [UI framework decision](issues/03-ui-framework-decision.md): **React + TypeScript.** Ecosystem argument was decisive — mature React bindings exist for every piece QueryForge needs (Monaco/CodeMirror, virtualized grids, docking/panel layout). Unblocks Data Grid (05).
- [Query editor decision](issues/04-query-editor-decision.md): **CodeMirror 6.** Autocomplete and formatting both downgraded to non-requirements, which erased both editors' usual selling points (CodeMirror's schema-completion helper, Monaco's minimap/command-palette); the deciding factor became Monaco's documented Electron-specific integration friction (worker/loader issues under `file://`/asar), which CodeMirror avoids by being worker-free. Surfaced two standing constraints now in Notes: no fee/licensed components, and current usage is local-only (no store, no selling, no CI yet).
- [Data grid decision](issues/05-data-grid-decision.md): **TanStack Table + TanStack Virtual.** AG Grid Community disqualified outright — its entire clipboard module (the spec's exact "copy cell/rows/values" requirement) is Enterprise-only. MUI X Community was viable but passed over to avoid Material Design lock-in and any future tier-surprise risk. Glide Data Grid passed over for mixed maintenance signals. Tradeoff: clipboard, resize UI, and row numbers are all hand-built.
- [Driver strategy + query-execution process model decision](issues/06-driver-strategy-decision.md): **Native JS/TS SDKs in-process, executed inside a single shared Electron `utilityProcess`** (not per-tab, not `worker_threads`, not a Java service). `utilityProcess` chosen for genuine OS-level crash containment (`worker_threads` shares main's fault domain and has an open 2025 Electron crash regression); one shared instance avoids fragmenting `mssql`'s per-tab connection pooling. Cancellation is asymmetric (SQL: real server-side cancel; Cosmos: client-side abandonment) — carried into ticket 10 as a contract requirement, not papered over. Unblocks ticket 10 (last blocker cleared).
- [Local persistence decision](issues/07-local-persistence-decision.md): **SQLite (`better-sqlite3`) for connection profiles/saved queries/query history + a JSON config file for preferences.** Hand-rolled schema migrations (version table + ordered `.sql` files), no migration library. (Its credential-split framing was superseded by ticket 08 — see below.)
- [Auth + credential storage decision](issues/08-auth-credential-storage-decision.md): **Self-rolled `safeStorage`-backed encryption for all secrets** (SQL credentials, Cosmos keys, MSAL token cache) as ciphertext in SQLite — no `@azure/msal-node-extensions`, no `keytar` (Microsoft's own official MSAL persistence package hard-depends on the same archived library ticket 01 flagged; a Microsoft-authored migration proposal has sat unanswered since June 2024). **Entra ID auth: interactive Authorization Code + PKCE via system browser + loopback redirect** (`acquireTokenInteractive`) — not device code (phishing-flagged), not ROPC (deprecated, breaking further Mar 2026), not embedded `BrowserWindow` (discouraged industry-wide). Unblocks ticket 10 (last blocker cleared); refines the Connection Manager's persistence boundary to "SQLite holds metadata + ciphertext, OS holds one opaque master key."
- [Distribution/packaging decision](issues/09-distribution-packaging-decision.md): **electron-builder, unsigned local builds for now** (macOS `.dmg`/`.zip`, Windows NSIS/portable `.exe`). No notarization, no code-signing cert, no auto-update — matches the local-only usage model. Tool chosen specifically so signing/auto-update can be flipped on later without migrating packaging tools if the usage model changes.
- [Provider Interface contract + §6 component boundaries decision](issues/10-provider-interface-contract.md): **Destination artifact, locked.** Surfaced and resolved a real contradiction first: `safeStorage` is Electron main-process-only and unreachable from ticket 06's shared `utilityProcess` — resolved by having main decrypt once at connect-time and hand plaintext to the utilityProcess over the main↔utility `MessagePort`, never persisted there. This fixed the Connection Manager's boundary (lives entirely in main; never holds a live DB connection) versus the Query Execution Service (the utilityProcess; owns live provider instances/pools). Locked the full §6 component list and the Database Provider Interface's method surface (`connect`/`testConnection`/`disconnect`/`executeQuery` returning a streamed `AsyncIterable<ResultChunk>`/`cancel(executionId)` with documented asymmetric semantics/`getMetadata`). All four accumulated flags (04, 06, 08) incorporated. Vocabulary recorded in `GLOSSARY.md`; the credential-handoff decision recorded as `adr/0001-decrypt-credentials-in-main-pass-plaintext-to-utility-process.md`. Flagged a test-strategy note into ticket 11 (not a blocker). No further tickets blocked by anything here.

- [Testing & CI tooling decision](issues/11-testing-ci-tooling.md): **Vitest** for unit tests (Provider Interface, application services); **Playwright's Electron support** for both main-process integration tests (`safeStorage` round-trip, the main↔utility `MessagePort` secret handoff) and renderer E2E, accepting its "experimental" label to keep one tool covering both; **Cosmos vNext Emulator via `testcontainers`** for fast Cosmos integration tests (free but not OSS — test-only tooling, outside the shipped-stack no-fee/OSS constraint) backed by a free-tier real Cosmos account for RU/feed-API fidelity gaps; **free-tier real Azure SQL Database** directly for SQL integration tests (no local SQL Server container — ARM64/Rosetta fragility made it not worth it); **Podman** over Docker Desktop for the container runtime; **CI pipeline explicitly deferred**, matching the local-only usage model. Last open ticket — map's Destination is fully locked.
